功能目标

02 / 08
🎯

核心目标

App 重启后恢复上次 workspace root、最近选中 spec、center view、last workspace state

👤

用户价值

不用每次重新选择目录并定位文件，提升连续工作流效率

🔧

技术边界

只负责单 workspace session 的持久化和恢复，不替代多 workspace 并行或 path safety

需持久化的 Session 字段

字段类型说明
workspace_rootstring规范化后的工作区根路径
selected_spec_pathstring最近选中的 spec 文件路径
center_viewstring当前视图模式 (specs/run/make)
last_workspace_stateenumdetected/unknown/invalid
last_detected_attimestamp最后状态探测时间

现状与目标差距

03 / 08

❌ As-Is 现状

  • App 重启后工作区状态完全丢失
  • 每次启动需重新选择 workspace root
  • 无法恢复上次查看的 spec 文件
  • 视图模式每次回到默认状态
  • workspace state 每次需完整重新探测
→

✅ To-Be 目标

  • 启动时自动加载上次 session
  • 自动恢复 workspace_root 并重新 detect-state
  • 恢复 selected_spec_path（如文件存在）
  • 恢复 center_view 视图模式
  • session root 不存在时优雅降级到选择页
用户痛点 高频切换项目时，每次重启需手动恢复工作流
技术差距 缺少 session 持久化机制 + path guard 校验
实现前提 依赖 MOD-workspace-root 的 path guard 和 detect-state

状态矩阵

04 / 08
启动条件 Session 状态 检测结果 系统行为 UI 反馈
valid session + root exists ✅ 已保存 ✅ path guard pass 恢复 workspace 并 detect-state 显示恢复的 root
valid session + root deleted ⚠️ root mismatch ❌ path guard fail 清空 session，回到选择页 提示重新选择
valid session + root unsafe ⚠️ unsafe path ❌ security check fail 清空 session，拒绝恢复 安全警告提示
no session / empty ❌ 无数据 — 进入 workspace 选择流程 显示选择对话框

Loading / Empty / Error 状态设计

⏳ Loading 恢复 session 中...
📂 Empty 无 session，引导选择 workspace
⚠️ Error path 不安全，显示原因

决策与取舍

06 / 08
推荐

方案 A: LocalStorage + Session Store

✅ 优势

  • 实现简单，无后端依赖
  • 重启即可恢复，用户感知即时
  • 不影响其他 workspace 功能

⚠️ 局限

  • 跨设备无法同步
  • 单用户单最近 session
备选

方案 B: IndexedDB 多 workspace 列表

✅ 优势

  • 支持多 workspace 快速切换
  • 可存储更多元数据

❌ 代价

  • 超出 MVP 范围
  • UI 复杂度提升
  • 需要 workspace 列表管理 UI
推荐方案 方案 A (MVP)
Why A 最小化实现，快速验证用户体验价值，方案 B 可作为 v2 扩展
Why Not B 当前 L4 scope 为单 workspace 闭环，多 workspace 需独立 spec
前提条件 MOD-workspace-root 的 path guard 和 detect-state 必须可用
切换条件 若用户反馈需要多 workspace 切换 → 触发 v2 spec
