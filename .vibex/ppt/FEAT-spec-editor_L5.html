FEAT-spec-editor_L5 — 问题背景

🔍 问题背景

现状痛点

  • spec 文件需要手工编辑 YAML，缺乏可视化界面
  • 编辑后无法实时验证 YAML 格式是否正确
  • spec 文件分布在多级目录 (L1~L5)，查找困难
  • 保存后缺少自动 lint 反馈

解决方案

  • SpecExplorer — 树形展示所有 spec 文件
  • SpecViewer — YAML 内容展示 + 在线编辑
  • 保存时自动触发 make lint-specs
  • lint 结果展示在 Output tab
SpecExplorer
点击文件节点
→
SpecViewer
展示 & 编辑 YAML
→
POST /api/workspace/specs/write
保存 + lint-specs
FEAT-spec-editor_L5 — I/O 契约

📦 Input / Output / Boundary

📥 Input

用户在 SpecExplorer 点击文件节点，或在 SpecViewer 点击「编辑」按钮

POST /api/workspace/specs/write

{ path, content } — 写入 spec YAML

📤 Output

读取：GET /api/workspace/specs/read/{path} → YAML 文本

写入：POST /api/workspace/specs/write → { success, error }

保存后：触发 make lint-specs → 显示验证结果

🚧 Boundary（边界约束）

只读写 specs/ 目录下的 YAML 文件，不读写其他目录

FEAT-spec-editor_L5 — 核心行为

⚙️ 实现行为 (Behaviors)

L5-B1 读取 spec 文件列表

onMount → GET /api/workspace/specs/list → 更新 spec_tree_store，显示树形结构按 L1~L5 分组

L5-B2 读取 spec 内容

点击节点 → GET /api/workspace/specs/read/{path} → 展示 YAML 内容在 SpecViewer textarea

L5-B3 保存 spec 修改

POST /api/workspace/specs/write { path, content } → 保存成功 → 调用 make lint-specs → 更新 Output tab

FEAT-spec-editor_L5 — 实现边界

✅ 允许 / 🚫 禁止

✅ 允许 (Allowed)

  • SpecExplorer 组件 — spec 文件列表读取
  • SpecViewer 组件 — YAML 内容展示 + 编辑
  • specs_write_handler — 写盘 + 调用 make lint-specs
  • specs_read_handler — 读 YAML 文件
  • 前端 YAML 编辑器 (textarea + js-yaml 预览)

🚫 禁止 (Forbidden)

  • 禁止读写 specs/ 目录外的文件
  • 禁止在 SpecViewer 保存后不触发 lint-specs
  • 禁止前端直接调用 make 命令
FEAT-spec-editor_L5 — 关键风险

⚠️ 失败条件 / 关键风险

⚠
前端读取不存在的 spec 文件不报错
⚠
保存 YAML 后不触发 lint-specs
⚠
specs_write_handler 读写 specs/ 外路径
⚠
lint 输出未展示在 Output tab
