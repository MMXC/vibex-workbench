🎯 实现目标

To-Be 目标

  • 用户在 SpecExplorer 点击「新建 L1」按钮
  • Wizard modal 展示表单（projectName / description / owner）
  • 从 spec-templates/L1-goal/ 加载模板
  • 用户填写 → 点击生成 → 文件写入
  • 成功：modal 关闭 → 新 spec 高亮选中
  • 失败：显示错误，modal 保持

✅ 完成标准

  • TC-newl1-1: 正常创建 → 文件存在，占位符正确替换
  • TC-newl1-2: 重名拒绝 → wizardError 显示，modal 不关闭
  • TC-newl1-3: 空项目名 → 前置校验阻断 API 调用
  • 模板 fetch 失败时 fallback 到内置最小模板
  • API 错误时正确捕获并展示

⚖️ 方案 A/B/不选理由

维度 方案A: Wizard Modal 方案B: 页面跳转 方案C: 右键菜单
开发成本 中（新建组件） 低（页面路由） 低

为何选/不选 ✅ 推荐：符合现有模式 ❌ 放弃：破坏导航连贯性 ❌ 放弃：入口隐蔽
决策结论: 采用方案A Wizard Modal，与现有 Explorer 操作模式一致，用户无需离开当前视图。

验证步骤与风险 L5 · Verification & Risk

🧪 验证与排错

验证步骤

  1. 刷新 SpecExplorer，按钮可见
  2. 点击「新建 L1」，modal 弹出
  3. 填写 projectName → 点击生成
  4. 检查文件 L1-goal/{name}.yaml 生成
  5. 验证文件内容占位符已替换
  6. 检查 modal 关闭 + 新文件选中

风险清单

模板文件不存在中Fallback 内置模板
API 返回错误中捕获并显示 wizardError
重名文件覆盖低后端应返回错误
空白 projectName低前置校验阻断
排错线索: 若文件未生成 → 检查 POST /api/workspace/specs/write 响应
若 modal 未关闭 → 检查 res.ok 判断逻辑
若内容未替换 → 检查正则替换是否全局匹配
