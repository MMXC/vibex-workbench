优化方向 · Why / Why-Not 决策

✅ 方案 A：独立 memory adapter 模块
why：解耦 journal 写入与记忆生成，便于独立测试和替换存储后端。
why not B（嵌入 journal writer）：journal writer 职责膨胀，单一职责被破坏；journal writer 改动风险高。
why not C（直接写 memplace/memlace）：无摘要逻辑，索引质量差；冲突处理无法统一。
前提：memplace/memlace 存储 schema 先行定义
✅ 方案 B：secret pattern filter 为独立 gate
why：安全红线不可绕过，独立 gate 便于审计和复用（其他写入路径）。
why not A（写入后扫描）：泄漏已发生，无法回滚；不符合安全设计原则。
前提：定义覆盖 token、env、credential 的 pattern 集合 切换条件：pattern 新增时 filter 实时生效
✅ 方案 C：stale_memory 置信度降级策略
why：避免频繁刷新 cost；保留历史线索供回溯。
why not A（强制刷新）：写入放大，journal 频繁更新时性能下降。
why not B（直接废弃旧记录）：丢失失败模式上下文，不利于根因分析。
前提：memplace/memlace 支持置信度字段 切换条件：journal timestamp 新于 memory 时触发
⚡ 关键约束（硬规则，不可绕过）
C1 memplace/memlace 不作为最终事实源
C2 memory 摘要不得包含 token/secret/完整 env value
切换条件 事实源始终是 spec + specs/journal/*.implementation.yaml
每张卡片回答 why / why-not，并标注前提条件和切换条件。覆盖开发视角的"方案怎么选"和 CTO 视角的"风险边界"。

决策页 · 推荐方案 & 成本风险

决策项 推荐方案 备选 取舍理由 成本 风险
模块位置 A: 独立 adapter 嵌入 journal writer 解耦优先，测试成本低 新增 1 模块 低
Secret 处理 B: 前置 gate 写入后扫描 安全红线不可妥协 pattern 库维护 中（pattern 漏配）
冲突处理 C: 置信度降级 强制刷新 / 废弃 平衡 cost 与上下文保留 schema 扩展 低
索引策略 spec+file+category 三维索引 全文检索 精确召回优先，性能好 索引维护逻辑 低
⚠ 风险与验证
  • R1：pattern 漏配导致 secret 泄漏 → 缓解：测试 TC-3 覆盖已知 pattern + 定期 regex 审查
  • R2：memory 与 journal 不同步 → 缓解：每次注入前强制回读 journal，memory 仅作加速层
  • R3：memplace/memlace 存储损坏 → 缓解：定期从 journal 重建，memory 幂等可覆盖

执行页 · 里程碑 & 验收标准

🗺 里程碑（M1–M3）
  • M1（Week 1）：定义 memplace/memlace schema；实现 secret pattern filter 并通过 TC-3
  • M2（Week 2）：实现 memory adapter（journal → memory → memplace）；通过 TC-1/TC-2
  • M3（Week 3）：集成读取验证路径；实现 stale_memory 标记；全链路回归测试
👤 负责人
  • 记忆模块开发：hermes
  • 安全审查（secret filter）：需安全 owner 评审
  • 测试：QA team（基于 TC-1/2/3）
✅ 验收标准（AC）
  • AC-1：journal 追加 checkpoint → memory adapter 同步 → memplace/memlace 出现压缩摘要
  • AC-2：memory 摘要与 journal 冲突 → 标记 stale_memory 并以 journal 为准
  • AC-3：memory 摘要含疑似 secret → 系统拒绝或脱敏该字段
🔄 回滚策略
  • memplace/memlace 损坏 → 从 specs/journal/*.implementation.yaml 重建
  • adapter 异常 → 降级：跳过 memory 层，直接读 journal
  • secret filter 误拦截 → 增加 pattern 白名单热更新机制
执行页覆盖测试视角（验收标准）和运维视角（回滚策略）。里程碑 M1–M3 清晰，负责人明确。

可复制问题清单 · 详情抽屉对话引导

以下问题用于 agent 详情抽屉继续对话，完善 spec 细节：

  • memplace/memlace 存储选型：SQLite / JSON 文件 / KV store？
  • secret pattern filter 初始覆盖哪些 pattern？（token、env、credential）
  • stale_memory 置信度字段 schema 如何定义？
  • memory adapter 是同步还是异步触发？
  • 写入失败时的重试策略是什么？
  • memplace/memlace 容量上限？过期清理策略？
  • 索引字段 spec name / file path / failure_category 的分词策略？
  • memory 与 journal 冲突的判定规则（timestamp 精度、schema 对比）？
  • TC-3（secret 过滤）的测试用例具体覆盖哪些 pattern？
  • 回滚时从 journal 重建 memory 的操作手册在哪？
  • adapter 降级路径是否有监控告警？
  • memory adapter 的性能基准（写入延迟、查询 QPS）要求是多少？

  • 🔴 高 secret filter 漏配（后果：数据泄漏）
  • 🟡 中 memory 与 journal 不同步（后果：上下文错误注入）
  • 🟢 低 存储性能瓶颈（后果：响应延迟）
