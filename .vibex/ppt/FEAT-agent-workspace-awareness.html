CTO 视角 Business Value & Risk

业务价值与架构风险

✅ 为什么做

  • 减少 agent 上下文不足导致的重复对话 — 降低 token 消耗与响应延迟
  • 标准化工作区感知接口 — 为未来多 agent 协作奠定基础
  • 差异化竞争优势 — 竞品缺乏的细粒度工作区感知能力

⚠️ 架构风险

  • 上下文膨胀风险 — workspace context 过大导致 token 超限
  • 性能回退 — 文件系统扫描延迟影响首响时间
  • 状态机复杂度 — empty/partial/ready 三态转换逻辑耦合
前提条件：context_manager 必须在 L3 完成，当前处于 L4 阶段依赖上游交付
切换条件：若 context_manager 延期超过 2 周，考虑降级为 lightweight workspace path only
CTO 视角：关注业务价值与风险。核心问题：这个功能值得投入吗？答案是肯定的，但需要控制上下文膨胀风险。

实现要点

  • awareness_injector.py — 统一注入接口，支持懒加载

Why Not 其他方案

  • 方案C（全局快照） — 实时性差，context 过期风险

执行页 Milestones & Rollback

里程碑与验收标准

里程碑

  • Week 1：workspace_context 核心实现
  • Week 2：awareness_injector + 状态机
  • Week 3：集成测试 + 性能调优
  • Week 4：E2E 验证 + 文档

验收标准

  • empty/partial/ready 三态转换正确率 100%
  • context 注入延迟 < 100ms
  • 单元测试覆盖率 > 90%
  • 无破坏性变更（向后兼容）

回滚策略

触发条件：E2E 测试失败率 > 5% 或 context 膨胀导致 OOM

回滚步骤：禁用 awareness_injector → 回退 workspace_context 版本 → 通知相关方

执行页：4周里程碑，2周核心实现 + 1周测试 + 1周验收。回滚策略：禁用注入层即可快速回退。
