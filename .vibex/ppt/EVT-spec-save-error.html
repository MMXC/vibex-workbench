实现目标与完成标准

🎯 核心目标

  • 捕获 wailsWriteSpecFile 写入失败

  • 保留用户编辑状态，不丢失数据
  • 提供可追溯的错误码与路径信息

✅ 完成标准

  • 保存失败时 UI 保留编辑内容
  • toast 显示错误摘要（≤ 80 字符）
  • 错误码映射表完整覆盖 5 种类型
  • SpecViewer 响应延迟 < 200ms
  • console 有完整 error 对象输出

决策页

✅ 推荐方案

事件驱动统一处理

  • 统一 event 总线，不限前端框架
  • 错误码枚举 + i18n 映射
  • SpecViewer 订阅，toast 订阅
成本：低（现有 event_bus 可复用）
风险：低（渐进增强）
Why not other: 硬编码 try-catch 不可复用

🔶 备选方案

Callback 回调模式

  • save() 返回 Promise<Result>
  • 调用方自行处理 error
成本：中（需改 API 签名）
风险：中（破坏性变更）
Why not: 分散错误处理，易遗漏
