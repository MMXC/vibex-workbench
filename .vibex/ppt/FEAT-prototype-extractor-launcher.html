功能目标 & 战略价值

🎯 核心目标

  • 在原型抽屉新增「浏览器完善区域」按钮
  • 一键唤起 Chrome 扩展 sidepanel
  • 打通 Workbench → 插件 → HTML 原型的完整链路

💡 战略价值（CTO 关注）

  • 自动化提效：减少人工抽取原型元素的时间成本
  • 生态闭环：插件 + Workbench 形成完整 spec → 原型 → 实现闭环
  • 可扩展：B2 支持多标签页并发（future）
⚠️
前提条件：用户已安装 L2-prototype-extractor Chrome 扩展（V1 手动安装）。插件安装引导 UI 属于 out_of_scope。

边界演示

边界条件 & 约束规则

🛡️ constraints.rules（来自 spec）

规则 ID 描述 触发方式
C1 仅支持 Chrome 浏览器（依赖 chrome.* API） 非 Chrome 环境下禁用按钮
C2 扩展必须在 Chrome Web Store 或本地加载 检测 chrome.runtime.id 是否存在
C3 传递 context 最大 2KB（chrome.storage.local 限制） 大型 spec 路径压缩
C4 FileWatcher 仅监听 .vibex/prototypes/ 目录 限定范围避免误触发

🔄 Out-of-Scope（明确不做）

  • ❌ 插件安装引导 UI（V1 手动安装）
  • ❌ 多标签页同时提取（单标签优先）
  • ❌ 提取进度实时推送（V2 WebSocket）
  • ❌ 提取失败自动重试（V2 retry queue）

📦 Dependencies

  • ✅ L2-prototype-extractor（Chrome 插件）
  • ✅ PrototypePanel（原型预览区，已实现）
  • ✅ FileWatcher（prototypes 目录监听）
🚫
Why-Not 说明：插件安装引导 UI 不在 V1 范围 → 降低实现复杂度，优先验证核心链路；多标签页 → 等核心链路稳定后再扩展。

受众 · 开发 & 测试

开发 & 测试关注点

👨‍💻 开发视角

  • UI 组件：PrototypePanel → 新增按钮（ghost 风格）
  • 接口调用：chrome.tabs.create + chrome.storage.local
  • 文件路径：.vibex/prototypes/{name}.html
  • 监听器：FileWatcher / fs.watch / chokidar

技术选型 Why

选型理由
chrome.tabs.create官方 API，sidepanel 最佳打开方式
chokidar 而非 fs.watch跨平台兼容，事件更可靠
chrome.storage.localsidepanel 共享数据的标准方案

🧪 测试视角

  • E2E：点击按钮 → sidepanel 打开 → 文件生成 → 预览刷新
  • 异常：未安装插件、Chrome 不可用、无 active spec
  • 边界：spec 路径超长（>2KB）、文件监听延迟

验收标准（测试 checklist）

  • ✅ 按钮在非 Chrome 浏览器下禁用
  • ✅ 未安装插件时显示 toast 提示
  • ✅ 文件生成后 3s 内预览刷新
  • ✅ context 正确传递（spec 路径 + workspace 根）

用户体验 & 方案决策

👤 用户视角

  • 入口：原型抽屉内 → 「浏览器完善区域」按钮
  • 操作：1 次点击 → Chrome 插件自动提取
  • 反馈：提取完成 → 原型预览自动刷新
  • 错误：未安装插件 → 友好提示 + 安装指引

用户旅程

打开原型抽屉
→
点击按钮
→
Chrome 插件提取
→
预览自动更新

⚖️ 方案决策

方案推荐理由
A: 直接打开 sidepanel ✅ 选用 官方推荐，用户体验最佳，无需额外页面
B: 弹窗输入 URL ❌ 不选 增加用户操作成本，与 sidepanel 体验差距大
C: 新标签页打开 ❌ 不选 sidepanel 是 Chrome 原生面板，与 Workbench 更紧密集成
成本 & 风险：开发成本低（~2pd）；主要风险为插件安装率低（需手动安装引导）。缓解：提供安装文档 + B3 友好提示。

执行 & 风险

执行计划 & 可复制问题清单

🚀 执行页

里程碑负责人验收标准
M1: 按钮 UI + B1 逻辑FE 开发点击后 sidepanel 打开
M2: B3 异常处理FE 开发未安装插件时显示提示
M3: FileWatcher + B2BE/集成文件生成后预览刷新
M4: E2E 测试QA覆盖所有状态矩阵场景

回滚策略

  • 功能开关控制（F2/F3 可独立禁用）
  • FileWatcher 热卸载，不影响原型抽屉基础功能
  • 按钮降级为纯外部链接（不传 context）

📋 可复制的问题清单（详情抽屉对话用）

  1. 按钮位置是否放在「浏览器完善区域」还是独立工具栏？
  2. context 传递是否需要加密或签名（防止篡改）？
  3. FileWatcher 是否需要支持 debounce（防抖）避免频繁刷新？
  4. B2 触发后是否需要 agent 推导确认弹窗？
  5. 插件未安装时的提示文案和链接路径是什么？
  6. 是否需要支持从 sidepanel 回调 Workbench（postMessage）？
  7. prototypes 目录初始为空时是否需要引导页？
  8. 多语言（i18n）文案是否需要提取到 locale 文件？
  9. 插件提取超时时间设置多少秒合理（建议 30s）？
  10. 是否需要埋点记录提取成功率用于监控？
  11. V2 多标签页并发时如何处理 context 冲突？
  12. FileWatcher 在 Windows WSL 环境下是否需要特殊处理？
