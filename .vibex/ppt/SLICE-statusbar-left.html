GOALS 实现目标与完成标准

🎯 What · 就绪状态与路径信息的精准呈现

目标项描述验收标准
实时就绪状态 显示当前环境/文件的就绪状态（ready/not-ready/error） 状态切换延迟 <100ms
路径信息展示 显示当前工作目录或文件路径（可配置） 路径截断时显示省略号，hover 显示完整路径
响应式布局 状态栏宽度变化时自动调整显示内容 无溢出、无截断错误
无障碍支持 符合 WCAG 2.1 AA 级对比度要求 色盲友好、屏幕阅读器可读
✅ Done 条件：所有状态转换正确 → 路径展示完整 → 无视觉溢出 → 自动化测试覆盖
🔄 切换条件：若状态展示与实际不符超过 3 秒 → 降级为 "unknown" 状态 → 触发告警

📏 验收口径
  • 所有边界条件必须通过自动化测试覆盖
  • 手动测试清单：窗口 resize、长路径、特殊字符、网络离线
  • 性能要求：状态切换 < 100ms，tooltip 显示 < 50ms
🔗 constraints.rules 引用： statusbar.always-visible、statusbar.left-priority、path.truncate-threshold=50

DECISION 决策页 · 推荐方案与执行计划

✅ 推荐方案

Pinia Store + CSS 截断 + CSS Transition
  • 复用现有 store 架构
  • 性能优先，减少 JS 计算
  • 动画流畅，GPU 加速
⚠️ 风险：store 耦合度高
💰 成本：约 2 人日

📋 执行计划

里程碑负责人验收标准回滚策略
M1: 状态同步 @dev-a 状态切换 < 100ms 回退 store 版本
M2: 路径渲染 @dev-b 截断 + tooltip 正常 隐藏路径组件
M3: 测试覆盖 @qa 边界用例 100% —
M4: 集成验收 @all E2E 通过 feature flag 关闭
👔 CTO 视角：预计工时 2 人日，风险可控，建议按 M1→M4 顺序迭代，每步可独立验收。
🧪 测试 视角：重点关注状态竞态、store 卸载后订阅清理、长路径截断边界。
