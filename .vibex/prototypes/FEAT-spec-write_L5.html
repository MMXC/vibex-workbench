Level 5 Implementation Spec

FEAT-spec-write_L5

SpecViewer 内联编辑功能实现

Frontend Proposal L5

文件路径: frontend/src/lib/components/workbench/SpecViewer.svelte

01 / 问题背景

为什么需要 SpecViewer 编辑功能？

  • 现状痛点：开发者需要退出 IDE 或使用外部编辑器修改 YAML 文件
  • 工作流断裂：浏览 spec → 编辑 spec → 验证 spec 被割裂在不同工具中
  • 效率瓶颈：频繁切换上下文增加认知负担，影响迭代速度
  • 目标：在 SpecViewer 中实现「浏览 → 编辑 → 保存」闭环
  • 范围限定：只做前端 UI 和 API 调用，不涉及后端文件写入逻辑

02 / IO 契约

输入 · 输出 · 边界

INPUT 输入
POST /api/workspace/specs/write { workspaceRoot: string, path: string, content: string // YAML 内容 }

触发时机：用户在 SpecViewer 点击「编辑」修改 YAML 后点击「保存」

OUTPUT 输出

成功：{ success: true, path: "..." }

失败：{ success: false, error: "..." }

前端收到成功后：切换只读模式 + 显示 toast「保存成功」

边界约束：只负责前端编辑 UI 和 API 调用，不实现 backend 写文件逻辑（已由 workspace_handlers.go 实现）

03 / 在总 Spec 中的位置

父子层级关系

  • 父 Spec：FEAT-spec-write（功能总纲）
  • 本 Spec：FEAT-spec-write_L5（实现层，Level 5）
  • 子 Spec：无
  • 依赖 Spec：无
  • 影响文件：frontend/src/lib/components/workbench/SpecViewer.svelte
职责定位：将 FEAT-spec-write 的「编辑保存」能力落地到具体 Svelte 组件实现

04 / 上下游关系

数据流向与相邻模块

  • 上游输入：用户交互（点击「编辑」按钮） + 原始 spec YAML 内容（从只读模式传入）
  • 下游影响：调用 workspace_handlers.go（POST /api/workspace/specs/write）
  • 相邻模块： → SpecExplorer.svelte（负责 spec 列表读取，非本 spec 范围） → SpecGraph.svelte（负责 spec 图谱渲染，非本 spec 范围） → lint-specs（负责 YAML 语法校验，非本 spec 范围）
  • 不涉及：不修改其他组件逻辑，保持边界清晰

05 / 验证方式与关键风险

测试场景与风险点

测试场景
  • TC-write-1：编辑 → 保存 → 只读模式（验证 API 参数正确性）
  • TC-write-2：保存 API 返回 500（验证错误处理与状态保持）
  • TC-write-3：取消编辑（验证状态恢复，无 API 调用）
关键风险
  • 并发冲突：多人同时编辑同一文件无提示
  • 内容丢失：浏览器崩溃时 editContent 未持久化
  • YAML 校验：保存前未校验语法（依赖 lint-specs）

06 / 状态变更摘要

新增状态与 UI 变化

新增 State
  • editing: boolean — 编辑模式开关
  • editContent: string — 编辑中的内容
  • saveLoading: boolean — 保存中状态
  • saveErr: string | null — 保存错误信息
  • hasUnsavedChanges: boolean — 是否有未保存修改
UI 条件渲染
  • 只读模式：{#if !editing} → <pre> + 「编辑」按钮
  • 编辑模式：{#if editing} → CodeMirror 编辑器 + 「保存」「取消」按钮

07 / 总结

FEAT-spec-write_L5 核心要点

  • 功能：在 SpecViewer 实现 YAML 内联编辑 + 一键保存
  • 入口：POST /api/workspace/specs/write，参数含 workspaceRoot / path / content
  • 边界：只做前端 UI + API 调用，不碰后端文件写入
  • 状态：editing / editContent / saveLoading / saveErr
  • 风险：并发冲突、内容丢失、YAML 校验缺失
成功标准：POST /api/workspace/specs/write 返回 { success: true } → 切换只读模式 + toast「保存成功」
